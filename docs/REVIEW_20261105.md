# Discovery, release and upstream review — 2026-11-05

## Scope

Reviewed the fork/upstream merge boundaries, remote target selection, StikServer transport and discovery, pairing placement, location connection cleanup, FFI/project linkage and release/source workflow. This is not a full security audit or physical-device verification of every feature. No repository/on-device Ideas collection was available.

## Findings corrected

- The nearby list queried only iOS `_remotepairing` services; server-owned Macs appeared only inside the StikServer page/target submenu. Added a native StikServer Devices section directly on the Devices page and a server browser for `_stikserver._tcp` plus role-checked `_stikdebug._tcp` compatibility advertisements.
- StikServer did not publish its server endpoint. The companion server now advertises its preferred physical LAN route, service role, protocol and authentication requirement. It never advertises a token. Selecting an untrusted discovered server clears the previous explicit token rather than transmitting it to a new host.
- Discovery includes peer-to-peer, retries without clearing the displayed list every frame, restarts on network/foreground changes and expires stale records. It resolves to numeric addresses, reducing reliance on host-app DNS behavior. LiveContainer can still restrict Bonjour according to its own host permissions/declarations; copied private links remain the independent fallback. No LiveContainer files were modified.
- Late messages from a replaced WebSocket are ignored. Malformed inventory produces an actionable error instead of silently retaining an empty list.
- Merge review restored internal access for upstream's cross-file pairing-placement tunnel method and the device detail page reused by the new list. Local connections use upstream's dynamic pairing port resolver; remote targets retain pinned pairing identities and address fallback. Partially created location connection handles are released before retries.
- The fork keeps its extra FFI declarations/overlay, persistent condition session, Devices tab, advanced/battery tools, native relay UI and remote target selection. Upstream launch/pairing/diagnostic/DDI/location features are retained. See UPSTREAM_SYNC_20261105.md for the complete imported commit list.
- StikDebug's build still publishes a GitHub Release after a successful archive. Added Conventional Commit notes from the previous stable release to the build commit, a source commit link and IPA SHA-256 sums. Nightlies have unique tags and do not delete/overwrite earlier stable or nightly releases. The manual release__nightly declaration is unchanged; stable dispatch still uses the IPA marketing version. Metadata release 1.0 is explicitly not Latest. AltSource channel creation and the final channel-removal line remain intact.
